# امپراتوری چوسان — بازی شبیه‌سازی مدیریت کشور

بازسازی وب‌محور بازی چت‌محور «امپراتوری چوسان» (که قبلاً با ChatGPT اجرا می‌شد). یک هوش
مصنوعی گیم‌مستر (از طریق OpenAI API) نقش راوی/کارگردان بازی را بازی می‌کند و بازیکن در
نقش «روهی کبیر»، پادشاه چوسان، تصمیم می‌گیرد.

سند کامل جهان، شخصیت‌ها، نهادها و قوانین بازی (که سیستم‌پرامپت گیم‌مستر از آن ساخته
می‌شود) اینجاست: [`../docs/joseon-game-bible.md`](../docs/joseon-game-bible.md).

## 🔗 روش ۱ (پیشنهادی): یه لینک واقعی بگیر — بدون نصب هیچی روی کامپیوترت

این روش بازی رو روی یک سرویس رایگان (Render) بالا می‌بره و در نهایت یک **لینک دائمی**
بهت می‌ده که هر وقت خواستی، از هر گوشی/کامپیوتری، فقط بازش می‌کنی و بازی می‌کنی — دیگه
لازم نیست دوباره این مراحل رو تکرار کنی.

### چیزی که لازم داری

یک کلید API از OpenAI. اگه نداری:
1. برو به [platform.openai.com/api-keys](https://platform.openai.com/api-keys)
2. ثبت‌نام/ورود کن، روی **Create new secret key** بزن، کلید رو کپی کن (یه چیزی شبیه
   `sk-proj-...`). این کلید رو فقط جایی که این راهنما می‌گه پیست کن، هیچ‌وقت جای دیگه‌ای
   (چت، ایمیل و...) به اشتراک نذار.

### مراحل دیپلوی

1. برو به [render.com](https://render.com) و با ایمیل یا حساب گیت‌هابت ثبت‌نام/ورود کن.
2. توی داشبورد، دکمه‌ی **New +** بالای صفحه رو بزن → **Blueprint** رو انتخاب کن.
3. ریپازیتوری گیت‌هاب `Roxavito/roxavito` رو انتخاب کن (اگه اولین باره، از Render بخواد به
   گیت‌هابت وصل بشه — اجازه بده).
4. Render خودش فایل `render.yaml` توی ریشه‌ی پروژه رو پیدا می‌کنه و سرویسی به اسم
   `joseon-empire` رو پیشنهاد می‌ده. تأیید کن.
5. توی فرمی که باز می‌شه، چهار فیلد می‌بینی: `OPENAI_API_KEY` و سه‌تای دیگه.
   `OPENAI_API_KEY` رو با کلیدی که از OpenAI گرفتی پر کن. برای `UPSTASH_REDIS_REST_URL`
   و `UPSTASH_REDIS_REST_TOKEN` (که وضعیت بازی رو دائمی نگه می‌دارن) اول بخش زیر
   («ذخیره‌ی دائمی بازی») رو انجام بده و مقادیرشون رو همین‌جا پیست کن — بدون این دو تا هم
   بازی اجرا می‌شه، فقط با هر دیپلوی بعدی از اول شروع می‌شه.
6. روی **Apply** / **Create Web Service** بزن و صبر کن (حدود ۲ تا ۵ دقیقه، اولین بار).
7. وقتی وضعیت سرویس شد **Live**، یه آدرس بالای صفحه می‌بینی شبیه:
   `https://joseon-empire.onrender.com` — همینه لینک بازیت! روش کلیک کن و بازی کن.

> 💡 توی پلن رایگان Render، اگه بازی چند دقیقه بدون استفاده بمونه سرویس می‌خوابه و اولین
> باری که دوباره لینک رو باز می‌کنی ممکنه ۳۰-۵۰ ثانیه طول بکشه تا بیدار بشه — طبیعیه، فقط
> صبر کن.

### 💾 ذخیره‌ی دائمی بازی (Upstash Redis، رایگان)

پلن رایگان Render دیسک دائمی نداره — یعنی هر بار که کد بازی آپدیت و دوباره دیپلوی بشه
(یا حتی گاهی خودکار)، وضعیت بازی و کل تاریخچه‌ی چتت پاک می‌شه و از اول شروع می‌کنی. برای
جلوگیری از این، بازی رو به یک دیتابیس رایگان Redis (سرویس Upstash) وصل می‌کنیم — کار
حدود ۲ دقیقه طول می‌کشه و هیچ هزینه‌ای نداره:

1. برو به [upstash.com](https://upstash.com) و با ایمیل یا گیت‌هاب ثبت‌نام/ورود کن.
2. توی داشبورد روی **Create Database** بزن، یک اسم بذار (مثلاً `joseon-empire`)، نوع رو
   **Redis** بذار و روی **Global** یا نزدیک‌ترین ریجن به سرویس Render‌ات بزن، بعد
   **Create** کن.
3. وارد صفحه‌ی همون دیتابیس شو و تب/بخش **REST API** رو باز کن. دو مقدار می‌بینی:
   `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` — این‌ها رو کپی کن.
4. این دو مقدار رو توی همون فرم دیپلوی Render (مرحله‌ی ۵ بالا) توی فیلدهای هم‌نام‌شون
   پیست کن.

از این به بعد وضعیت زنده‌ی بازی (وضعیت کشور، دربار، وظایف، نامه‌ها، تاریخچه‌ی کامل چت)
لحظه‌به‌لحظه توی همین دیتابیس ذخیره می‌شه و با دیپلوی بعدی از بین نمی‌ره — فقط اگه خودت
دکمه‌ی «شروع دوباره» رو بزنی پاک می‌شه.

> اگه این مرحله رو رد کنی، بازی همچنان کار می‌کنه (روی دیسک محلی سرور ذخیره می‌شه)، فقط
> هر دیپلوی بعدی رو از اول شروع می‌کنی. هر وقت خواستی می‌تونی بعداً هم این دو تا فیلد رو
> توی داشبورد Render، بخش **Environment** سرویس `joseon-empire`، اضافه کنی.

### اگه چیزی جواب نداد

- **صفحه‌ی «Application failed to respond» یا خطا موقع build:** توی داشبورد Render، روی
  سرویس `joseon-empire` بزن → تب **Logs** رو باز کن، آخرین خطوط قرمز رو کپی کن و همون‌جا
  توی چت برام بفرست تا کمک کنم.
- **پیام خطا وقتی توی بازی پیام می‌فرستی:** معمولاً یعنی کلید OpenAI اشتباهه یا حساب
  OpenAI شارژ/بیلینگ نداره — توی داشبورد Render برو **Environment** و مقدار
  `OPENAI_API_KEY` رو چک کن، و توی پنل OpenAI هم بیلینگ حسابت رو چک کن.

## 🖥 روش ۲: اجرا روی کامپیوتر خودت (برای کسی که کنجکاوه یا نمی‌خواد آنلاینش کنه)

این روش نیاز به نصب Node.js و کار با ترمینال داره — اگه روش ۱ برات کافیه لازم نیست این
بخش رو بخونی.

<details>
<summary>باز کن</summary>

### قدم ۱ — نصب Node.js (یک‌بار، روی کل کامپیوتر)

1. برو به [nodejs.org](https://nodejs.org)
2. دکمه‌ی سبزرنگی که نوشته **LTS** رو دانلود و نصب کن (Next → Next → Install، مثل هر نرم‌افزار دیگه).

### قدم ۲ — باز کردن ترمینال توی پوشه‌ی پروژه

- **ویندوز:** پوشه‌ی `roxavito` رو باز کن، توی فضای خالی پوشه راست‌کلیک کن و **«Open in Terminal»** رو بزن.
- **مک:** توی Finder پوشه‌ی `roxavito` رو باز کن، راست‌کلیک → **Services → New Terminal at Folder**.

### قدم ۳ — سرور (بک‌اند)

```bash
cd game/server
npm install
```

یه فایل جدید دقیقاً به اسم `.env` توی پوشه‌ی `game/server` بساز و این رو توش بنویس
(کلید واقعی OpenAI خودت رو بذار):

```
OPENAI_API_KEY=your-openai-api-key-here
OPENAI_MODEL=gpt-4o
```

بعد:

```bash
npm run dev
```

این پنجره رو باز نگه دار.

### قدم ۴ — رابط بازی (فرانت‌اند)

یک پنجره‌ی ترمینال **جدید** باز کن:

```bash
cd game/client
npm install
npm run dev
```

### قدم ۵ — بازی کردن

مرورگر رو باز کن، برو `http://localhost:5175`.

## معماری

```
game/
├── server/   بک‌اند Node.js + Express — تماس با OpenAI API، مدیریت وضعیت بازی (save)،
│             و (وقتی client build شده باشه) سرو کردن خود رابط بازی از همون پورت
└── client/   فرانت‌اند React + Vite — چت با گیم‌مستر + پنل‌های وضعیت زنده (خزانه/ارتش/جناح‌ها/...)
```

`render.yaml` (در ریشه‌ی ریپو) پیکربندی دیپلوی Render رو مشخص می‌کنه: کلاینت رو build
می‌کنه، وابستگی‌های سرور رو نصب می‌کنه، و سرور رو اجرا می‌کنه — همه در یک سرویس با یک URL.

- **چرا بک‌اند لازم است:** کلید API هرگز نباید در مرورگر قرار بگیرد. سرور تنها واسط امن
  بین کلاینت و OpenAI API است و همچنین وضعیت بازی (save) را روی دیسک نگه می‌دارد.
- **ذخیره‌سازی:** ساده و فایل‌محور (`server/data/state.json` و `history.json`). روی Render
  پلن رایگان این فایل‌ها روی دیسک موقتی هستند — اگه سرویس ری‌استارت/ری‌دیپلوی بشه، بازی از
  نقطه‌ی شروع دوباره آغاز می‌شود. برای ذخیره‌ی دائمی روی هاست، باید یک دیسک دائمی (Render
  Disk) یا دیتابیس واقعی اضافه کرد.
- **مکانیزم وضعیت زنده:** گیم‌مستر در انتهای هر پاسخ یک بلوک JSON مخفی (`<STATE>...</STATE>`)
  برمی‌گرداند که سرور آن را استخراج، با وضعیت قبلی ادغام (merge) و ذخیره می‌کند. این بخش هرگز
  به کاربر نمایش داده نمی‌شود — فقط پنل‌های وضعیت را در فرانت‌اند به‌روزرسانی می‌کند.
- **ساختار حکومت (شخصیت‌ها/نهادها) در کد قفل شده**، نه در خروجی مدل — دقیقاً طبق یکی از
  مهم‌ترین قوانین طراحی استخراج‌شده از بازی اصلی: «تغییر پرسنل فقط با رویداد درون‌داستانی
  مجاز است، نه فراموشی یا خطای مدل».

## تنظیمات

| متغیر | توضیح | پیش‌فرض |
|---|---|---|
| `OPENAI_API_KEY` | کلید API اوپن‌ای‌آی (الزامی) | — |
| `OPENAI_MODEL` | مدل مورد استفاده برای گیم‌مستر | `gpt-4o` |
| `OPENAI_MAX_TOKENS` | سقف توکن خروجی هر پاسخ | `4096` |
| `PORT` | پورت سرور (روی Render خودکار تنظیم می‌شود) | `8787` |
| `UPSTASH_REDIS_REST_URL` | آدرس REST دیتابیس Redis برای ذخیره‌ی دائمی بازی (اختیاری، توضیح بالا) | — (بدون آن: دیسک محلی) |
| `UPSTASH_REDIS_REST_TOKEN` | توکن REST همان دیتابیس | — (بدون آن: دیسک محلی) |

## شروع دوباره‌ی بازی

دکمه‌ی «شروع دوباره» در بالای صفحه، تاریخچه و وضعیت را پاک کرده و بازی را از نقطه‌ی
شروع (`server/data/initial-state.json`) دوباره آغاز می‌کند.

## محدودیت‌های نسخه‌ی فعلی (MVP) و ایده برای توسعه‌ی بعدی

- بدون streaming — پاسخ گیم‌مستر یک‌جا نمایش داده می‌شود (نه تایپ تدریجی).
- بدون احراز هویت/چندکاربره — یک بازی مشترک برای هرکسی که به لینک دسترسی داشته باشد؛
  برای بازی خصوصی/چندکاربره واقعی نیاز به توسعه دارد.
- ذخیره‌سازی دائمی (Upstash Redis) اختیاری است — اگر وصل نشود، بازی همچنان روی دیسک
  موقتی هاست رایگان کار می‌کند، فقط با هر دیپلوی از نو شروع می‌شود (بالا توضیح داده شد).
- تاریخچه‌ی کامل مکالمه هر بار به مدل ارسال می‌شود؛ در صورت طولانی‌شدن خیلی زیاد بازی،
  ممکنه لازم بشه تاریخچه خلاصه‌سازی (summarize) بشه تا از سقف کانتکست مدل رد نشه.
- کدکس/دانشنامه‌ی درون‌بازی (طومارهای یانگ چئول) هنوز به UI اضافه نشده؛ در سند
  `joseon-game-bible.md` بخش ۷ مستند شده و می‌تواند بعداً به یک پنل تبدیل شود.
